# Technical Research — Phase 6.3: Mobile Production & Publishing

## 1. CI/CD & Delivery (EAS Build)

### `eas.json` Best Practices
- **Inheritance**: Use `extends` to share common settings across profiles.
- **Profiles**:
    - `development`: Points to local API / dev server.
    - `preview`: Points to **Production API** with `distribution: internal`. Used for internal testing and APK direct distribution.
    - `production`: Points to **Production API** with `distribution: store`.
- **Environment Variables**: Use EAS Secrets/Environment Variables instead of `.env` files. Sync with `eas env:pull`.
- **Binary Stability**: Set `runtimeVersion` (policy: "appVersion") to prevent incompatible OTA updates.

## 2. Push Notifications (End-to-End)

### Backend (NestJS + `expo-server-sdk`)
- **Token Management**: Store `expoPushToken` in a `UserDevice` table (Linked to `User`).
- **Chunking**: Use `expo.chunkPushNotifications()` to optimize delivery.
- **Async Delivery**: Use BullMQ (already in project) to send notifications asynchronously.
- **Cleanup**: Invalidate tokens that return `DeviceNotRegistered` error.

### Mobile (React Native + `expo-notifications`)
- **Permissions**: Request `NOTIFICATIONS` permission on app start or during onboarding.
- **Listeners**: Use `useNotificationObserver` pattern to handle notifications in foreground/background.
- **ProjectId**: Explicitly pass `projectId` from `app.json` when calling `getExpoPushTokenAsync` to ensure consistency in production.

## 3. KYC & Secure Uploads

### Pattern: Pre-signed URLs
- **Direct Upload**: Mobile app uploads directly to S3/Cloudinary/Firebase Storage via a time-limited `PUT` URL.
- **Backend Flow**:
    1. Mobile requests URL: `POST /kyc/upload-url`.
    2. Backend generates Pre-signed URL via Cloud SDK.
    3. Mobile uploads binary to URL.
    4. Mobile confirms completion: `POST /kyc/submit`.
- **Privacy**: Buckets must be **PRIVATE**. Access is only granted via temporary URLs for Admin review.

## 4. Offline Persistence

### AsyncStorage
- **Scope**: Ideal for "Offline Lite" (Active Order & User Profile).
- **Strategy**: 
    - Read from `AsyncStorage` on app mount to hydrate state.
    - Update `AsyncStorage` on every successful API fetch/mutation (Cache-aside).
- **Connectivity**: Use `@react-native-community/netinfo` to detect offline state and toggle the "No Connection" banner.
