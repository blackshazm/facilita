# Phase 6.2 Summary: Fiscal Compliance & Tax Engine

## Achievement summary
Phase 6.2 successfully established the fiscal foundation for the FACILITA platform. We implemented a dynamic tax engine capable of handling current Brazilian tax rules and the upcoming **Reforma Tributária 2026 (IBS/CBS)**. The system now automatically issues invoices (mocked via eNotas) and maintains an immutable audit log for all financial transactions, ensuring transparency and compliance.

## Key Changes

### 1. Fiscal Engine & Strategies
- **Strategy Pattern**: Implemented `TaxStrategy` with two concrete strategies:
    - `CurrentTaxStrategy`: Handles current 20% commission model.
    - `Reforma2026Strategy`: Implements projections for IBS (17.7%) and CBS (8.8%) applied to the marketplace fee.
- **Auto-Switching**: `TaxCalculatorService` automatically switches to the 2026 strategy for transactions scheduled on or after January 1st, 2026.

### 2. NFS-e Automation
- **eNotas Adapter**: Created a gateway adapter for NFS-e emission (currently mocked for development).
- **Event-Driven Emission**: Integrated a `FiscalInvoiceEventListener` that reacts to `payment.captured` events to trigger invoice creation asynchronously.
- **Invoice Tracking**: Added an `Invoice` model to the database linked to payments.

### 3. Financial Audit Log
- **Immutability**: Established a `FinancialAuditLog` model in a dedicated `audit` schema.
- **Service Integration**: `CapturePaymentUseCase` now explicitly logs state changes (before/after) during the capture process.
- **Traceability**: All financial actions now leave a permanent, append-only record with actor and metadata tracking.

### 4. Code Hardening
- **Refactoring**: Updated `CapturePaymentUseCase` to remove hardcoded split logic and use the new `TaxCalculatorService`.
- **Typing**: Improved type safety in the payment domain to support fiscal fields (`ibsAmount`, `cbsAmount`, `invoiceId`).
