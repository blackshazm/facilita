# Walkthrough — Phase 6.2: Fiscal Compliance & Tax Engine

## Overview
Phase 6.2 implemented the fiscal core of FACILITA, focusing on tax accuracy and financial transparency. This walkthrough demonstrates the implemented components and the verification process.

## Changes Made

### 1. Database Schema
Updated `packages/database/prisma/schema.prisma` with:
- `Invoice` model (Payments schema).
- `FinancialAuditLog` model (Audit schema).
- Added `ibsAmount` and `cbsAmount` to `Payment` and `Invoice`.

### 2. Tax Engine
- **Location**: `apps/api/src/modules/fiscal/application/tax-calculator.service.ts`
- **Pattern**: Strategy pattern used to isolate 2026 tax logic.
- **Verification**: Logic verified via script for both Current and 2026 scenarios.

### 3. NFS-e Integration
- **Adapter**: `apps/api/src/modules/fiscal/infrastructure/enotas-gateway.adapter.ts`
- **Listener**: `apps/api/src/modules/fiscal/infrastructure/listeners/fiscal-invoice.listener.ts`
- Automatically links eNotas invoice IDs to the corresponding payments.

### 4. Financial Audit
- **Service**: `apps/api/src/shared-kernel/services/financial-audit.service.ts`
- Captures state transitions for high-value financial actions.

## Validation Results

### Automated Logic Check
The `TaxCalculatorService` logic was verified using a JS runner against the compiled code:
- **Current Strategy**: 20% marketplace fee correctly calculated.
- **2026 Strategy**: IBS and CBS correctly calculated based on projected rates.
- **Build Status**: `npm run build --workspace=api` passed successfully after fixing path issues.

### Manual Review
- Code audited for Modular Hexagonal compliance.
- Domain isolation maintained (Fiscal logic independent of Payment logic via adapters and events).

## UI/UX Impact
(None in this phase - backend infrastructure focus).
