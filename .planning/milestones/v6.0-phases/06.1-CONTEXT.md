# Phase Context — 06.1: Operational Analytics & BI

**Date**: 2026-05-05
**Status**: Context Gathered

## Domain
The core domain for this phase is **Marketplace Intelligence**. We are implementing the systems required to aggregate operational data into actionable KPIs, providing the Backoffice team with visibility into the health and performance of the platform.

## Decisions

### 1. Data Aggregation & Persistence
- **D-01: Event-Driven Read Models**: Instead of real-time SQL aggregations on transactional tables, we will implement a new `Analytics` module that listens to domain events (`OrderCompletedEvent`, `PaymentCapturedEvent`, etc.).
- **D-02: Projection Tables**: The `Analytics` module will maintain its own optimized tables (e.g., `DailyMetrics`, `ProviderStats`) updated asynchronously via events. This ensures high performance and module isolation (Modular Hexagonal).

### 2. Dashboard & Visualization
- **D-03: Recharts Integration**: We will use the `Recharts` library for all dashboard visualizations in the Admin Backoffice. Charts must follow the **Emerald 2.0** aesthetic (clean, premium, responsive).
- **D-04: Real-time Updates**: The dashboard will fetch data via standard React Query hooks with a configurable stale time (e.g., 5 minutes), rather than WebSockets, to maintain simplicity.

### 3. Reporting & Export
- **D-05: Server-side Generation**: Reports for ANL-03 will be generated on the backend. We will implement a streaming CSV export to handle large datasets efficiently.
- **D-06: API Endpoint**: A dedicated `/api/analytics/export` endpoint will be created, protected by `RolesGuard(UserRole.ADMIN)`.

## Code Context & Patterns
- **Events**: Reference the `EventEmitter2` implementation in `apps/api/src/modules/payments` for cross-module communication.
- **Admin UI**: Extend the existing structure in `apps/client/src/app/admin`.
- **Financial Precision**: All monetary metrics (GMV) must continue to use **Integers in Cents** (BigInt) for calculation, as established in Phase 5.1 (D-01).
