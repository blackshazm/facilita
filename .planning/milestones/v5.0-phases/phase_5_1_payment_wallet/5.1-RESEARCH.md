# Phase 5.1: Payment Escrow & Wallet Module - Research

## Technical Domain Research

### 1. Pagar.me V5 Integration (Escrow & Split)
The "Escrow" requirement is best met using Pagar.me's **Auth-Only** flow for Credit Cards and **Transfer Settings** for funds holding.

- **Credit Card Flow**:
  - **Authorization**: Create an order with `operation_type: "auth_only"`. This blocks the customer's limit but doesn't capture funds.
  - **Capture**: Call the `/capture` endpoint when the order status moves to `DONE`.
  - **Split Definition**: Split rules (recipient share, fees, liability) can be defined at creation or capture.
- **PIX Flow**:
  - Since PIX is always immediate, we use `transfer_enabled: false` on the recipient's configuration to hold the provider's share in the Pagar.me balance until the platform releases it.
- **Precision**: Use basis points (e.g., 1000 for 10.00%) for percentage-based splits and cents for flat-rate splits.

### 2. Ledger & Wallet Design (Double-Entry)
To ensure auditability, the `Wallet` system will follow a simple ledger pattern:
- **BigInt Storage**: All balances and transactions stored as **BigInt (cents)**.
- **Transaction Types**:
  - `FROZEN`: Amount credited to `pendingBalance` upon payment authorization.
  - `CREDIT`: Amount moved from `pendingBalance` to `balance` after service completion and retention period.
  - `DEBIT`: Payout triggered to the provider's bank account.
  - `CANCEL`: Reversal of frozen or available balance.

### 3. Payout Scheduler (BullMQ)
The platform will automate payouts based on the provider's Tier:
- **Delay Logic**:
  - Bronze: D+15.
  - Prata: D+7.
  - Ouro: D+2.
- **Implementation**: When `OrderDoneEvent` is fired and payment is captured, a BullMQ job is scheduled with a `delay` calculated based on the `ProviderTier`.

## Proposed Schema Changes (Prisma)

### Identity Schema
```prisma
enum ProviderTier {
  BRONZE
  PRATA
  OURO
  @@schema("identity")
}

model ProviderProfile {
  // ... existing fields
  tier               ProviderTier @default(BRONZE)
  pagarmeRecipientId String?      @unique
}
```

### Payments Schema
```prisma
model Wallet {
  id             String              @id @default(uuid())
  providerId     String              @unique
  balance        BigInt              @default(0) // Cents
  pendingBalance BigInt              @default(0) // Cents
  transactions   WalletTransaction[]
  @@schema("payments")
}

model WalletTransaction {
  id          String          @id @default(uuid())
  walletId    String
  wallet      Wallet          @relation(fields: [walletId], references: [id])
  type        TransactionType
  amount      BigInt
  orderId     String?
  externalId  String?
  description String?
  createdAt   DateTime        @default(now())
  @@schema("payments")
}

enum TransactionType {
  CREDIT
  DEBIT
  FROZEN
  CANCEL
  @@schema("payments")
}
```

## Validation Architecture
- **Financial Integrity**: A script to verify that `Wallet.balance == SUM(WalletTransaction.amount)`.
- **Webhook Idempotency**: Test cases with duplicate Pagar.me payloads.
- **Tier Accuracy**: Unit tests for the `PayoutDelayCalculator`.
