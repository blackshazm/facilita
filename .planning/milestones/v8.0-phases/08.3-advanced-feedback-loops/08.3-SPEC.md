# SPEC.md: Phase 08.3 - Advanced Feedback Loops

## 1. Goal
Implement a double-blind, bidirectional review system to capture granular feedback and visual evidence, safeguarding platform quality without introducing bias or retaliation.

## 2. Boundaries

### In Scope
- A new `reviews` Prisma schema and `Review` model for storing feedback from both Customers and Providers.
- Customer-side review flow capturing 3 metrics (Punctuality, Technical Skill, Cleanliness), a text comment, and up to 3 photo URLs.
- Provider-side review flow capturing a single 1-to-5 rating and a text comment for the Customer.
- A double-blind visibility rule: reviews are hidden until either both parties submit their review, or 7 days elapse after the order completes.
- Asynchronous update of the `ProviderProfile.rating` via an event when a review becomes visible.

### Out of Scope
- Dynamic Provider Ranking search algorithm adjustments (QUAL-04 - deferred to future).
- AI Sentiment analysis of the review text (OPS-03 - deferred to future).
- Uploading mechanism for the photos (we assume the client already has pre-signed URLs or an existing bucket logic and just sends the final URLs to the API).

## 3. Requirements

### QUAL-01: Multi-Category Service Rating
- **Current State:** No review table exists. Provider rating is a static `5.0` default.
- **Target State:** Customer can submit a review with three distinct 1-to-5 scores (Punctuality, Technical Skill, Cleanliness) for a completed Order.
- **Acceptance Criteria:** [ ] API accepts a payload with the three category scores and calculates the review's overall score as their simple average.

### QUAL-02A: Bidirectional Feedback
- **Current State:** Providers cannot review Customers.
- **Target State:** Providers can submit a review for the Customer containing a single 1-to-5 score and a text comment.
- **Acceptance Criteria:** [ ] API accepts provider review payloads and correctly identifies the author role.

### QUAL-02B: Double-Blind Visibility
- **Current State:** N/A.
- **Target State:** Reviews remain in a `HIDDEN` logical state. A review's content is only returned by the API if the other party has also submitted a review for the same Order, OR if `now() > order.completedAt + 7 days`.
- **Acceptance Criteria:** [ ] API endpoint for fetching reviews returns redacted/hidden content if the double-blind conditions are not met.

### QUAL-03: Evidence-Linked Feedback
- **Current State:** Evidence is only collected during the service workflow (Before/After).
- **Target State:** Customer review payload accepts an array of up to 3 `photoUrls` which are saved in the new Review model.
- **Acceptance Criteria:** [ ] API rejects review submissions with more than 3 photos, and correctly persists valid photo URLs.

### QUAL-05: Rating Aggregation
- **Current State:** `ProviderProfile.rating` is never recalculated.
- **Target State:** When a review becomes visible, an event `review.revealed` is dispatched to asynchronously recalculate the Provider's overall average rating and update their `ProviderProfile`.
- **Acceptance Criteria:** [ ] The provider's global rating updates to reflect the average of all their visible reviews.
