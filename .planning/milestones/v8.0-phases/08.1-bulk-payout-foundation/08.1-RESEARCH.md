# Research: Phase 08.1 — Bulk Payout Foundation

## Pagar.me v5 Integration

### 1. Balance Check
- **Endpoint**: `GET /recipients/{recipient_id}/balance`
- **Authentication**: Basic Auth (Secret Key).
- **Master Recipient**: We need to use the `PAGARME_MASTER_RECIPIENT_ID` from env vars to check the marketplace's own balance before triggering payouts.
- **Payload Response**: 
  ```json
  {
    "available": 100000,
    "waiting_funds": 50000,
    "transferred": 0
  }
  ```

### 2. Transfer Idempotency
- **Header**: `idempotency-key`
- **Value**: Ledger Entry UUID. This is already implemented in `PagarMePayoutAdapter`, but must be enforced in the batch worker.

### 3. Error Codes for Interruption
- **Insufficient Funds**: The API returns a `400 Bad Request` or `422 Unprocessable Entity` with a specific error code (e.g., `insufficient_funds`).
- **Strategy**: The `BatchPayoutProcessor` will catch this specific error, mark the batch as `FAILED_NO_FUNDS`, and stop processing further jobs in that batch.

## BullMQ Orchestration

### Queue Configuration
- **Name**: `payout-batch-queue`
- **Concurrency**: `2` (as decided in Discussion).
- **Retry Policy**: 3 attempts with exponential backoff, but *only* for network errors. Logic errors or "Insufficient Funds" should be terminal for the item.

### Job Data Payload
```typescript
{
  batchId: string;
  ledgerId: string;
  providerId: string;
  recipientId: string;
  amount: number;
}
```

## Database Schema (Prisma)
We need a new `PayoutBatch` model to track the lifecycle of a bulk operation:
```prisma
model PayoutBatch {
  id          String   @id @default(uuid())
  adminId     String
  totalAmount BigInt
  totalCount  Int
  processedCount Int @default(0)
  status      String   // PENDING, PROCESSING, COMPLETED, FAILED_PARTIAL, FAILED_NO_FUNDS
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  items       Ledger[] // Relation to Ledger entries
}
```

## Frontend Polling
- **Interval**: 3000ms.
- **State Management**: React state for `isProcessingBatch` and `currentBatchId`.
- **UI**: Display a linear progress bar in the toast or top of the table.
