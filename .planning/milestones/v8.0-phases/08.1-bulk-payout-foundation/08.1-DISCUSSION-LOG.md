# Discussion Log: Phase 08.1 — Bulk Payout Foundation

**Date**: 2026-05-08
**Participants**: User, the agent

## Summary of Decisions

### Area 1: API & Batch Strategy
- **Option Selected**: Single POST endpoint `/admin/payouts/batch`.
- **Rationale**: Cleanest architecture for BullMQ orchestration and status tracking.

### Area 2: Progress Feedback
- **Option Selected**: Polling.
- **Rationale**: Socket.io is not present in the current stack; Polling provides a robust alternative without adding library overhead.

### Area 3: Concurrency
- **Option Selected**: Concurrency level 2.
- **Rationale**: Balance between speed and gateway safety (rate limits/balance checks).

### Area 4: UI/UX
- **Decision**: Dedicated tab in Payouts dashboard, multi-select with shift-click, persistent toasts for status.
