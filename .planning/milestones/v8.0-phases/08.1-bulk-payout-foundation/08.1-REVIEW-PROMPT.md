## Phase 08.1: Bulk Payout Foundation
### Roadmap Section
**Goal**: Enable administrative batch processing of provider payouts with strict safety controls.
- **Requirements**: PAY-04, PAY-06, OPS-02.
- **Success Criteria**:
    - Admin can select 10+ payouts and process them with one click.
    - Payouts are blocked if gateway balance is insufficient (Real-time check).
    - Idempotency keys prevent double transfers during manual retry.

### Requirements Addressed
- **PAY-04**: Batch Payout Processing. Admin can select multiple pending payouts and execute them in a single batch operation.
- **PAY-06**: Batch Idempotency Control. Every payout in a batch must be linked to a unique transaction ID to prevent duplicate transfers on retries.
- **OPS-02**: Real-time Financial Gateway Balance. Admin dashboard must display the actual balance available in Pagar.me versus the internal ledger.

### User Decisions (CONTEXT.md)
- **D-01: Endpoint de Lote**: Criar `POST /admin/payouts/batch` que recebe um array de IDs de Ledger.
- **D-02: BullMQ Strategy**: Concorrência limitada a 2.
- **D-03: Idempotência**: `idempotency_key` = Ledger UUID.
- **D-04: Monitoramento**: Polling no Frontend.
- **D-05: Notificações**: Toasts persistentes.
- **D-07: Balance Check**: Consultar saldo antes do lote e interromper em falha.

### Research Findings
- **Balance Endpoint**: `GET /recipients/{id}/balance`.
- **Error Code**: `insufficient_funds` handled to mark batch as `FAILED_NO_FUNDS`.
- **Database Model**: `PayoutBatch` added to track progress and state.
