# Phase 09.2: Operational Dashboard - Research

## Architecture Patterns

### Frontend (`apps/client/src/app/admin`)
- **Framework:** Next.js 15 App Router.
- **Data Fetching:** SWR or React Query with a polling interval of 30-60 seconds for dashboard data (per D-02).
- **Layout Structure:** High-level summary cards routing to detailed lists for deep dives.
- **Design System:** `shadcn/ui` with `radix-ui` and `lucide-react` (as per UI-SPEC). Typography and specific colors (Emerald as Accent, Red as Destructive) configured in Tailwind.
- **State Management:** React local state for modals (like the Bulk Payouts confirmation modal, D-03).

### Backend (`apps/api`)
- **Modules Involved:**
  - `analytics` module: Will need endpoints to aggregate financial metrics (payouts, chargebacks) and quality metrics (ratings, disputes).
  - `payments` module: Will need endpoints to trigger/halt bulk payouts and log the audit action (who, when, what).
- **Infrastructure:**
  - `BullMQ` + `Redis` for executing the actual bulk payouts in the background. The dashboard will just trigger/halt the job queues.

## Validation Architecture
- **Financial Metrics (DASH-01):** API must accurately return aggregated payouts and chargebacks.
- **Quality Metrics (DASH-02):** API must calculate provider ratings and dispute ratios, supporting snapshot data and simple trend indicators.
- **Bulk Payouts (DASH-03):** Trigger/Halt actions must insert an audit log and correctly pause/resume the BullMQ queues in the `payments` module. Modal requires explicit text confirmation ("CONFIRMAR").

## Implementation Strategy
- **Step 1:** Backend - Expand `analytics` and `payments` module endpoints for dashboard data and payout controls.
- **Step 2:** Frontend - Setup polling hooks for data fetching.
- **Step 3:** Frontend - Build high-level summary cards (Financial & Quality).
- **Step 4:** Frontend - Build granular list views for drill-downs.
- **Step 5:** Frontend - Build the Bulk Payout control panel with the confirmation modal.
