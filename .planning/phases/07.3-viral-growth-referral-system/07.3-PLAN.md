# Plan — Phase 7.3: Viral Growth & Referral System

## Overview
Implement the referral system with a D+15 delayed reward of R$ 10,00 (Promotional Credit) for both the referrer and referee. This includes tracking invite codes, detecting fraud (Sybil attacks), automatically applying discounts, and handling edge cases like code collisions and order cancellations.

## Wave 3: D+15 Reward Trigger & Processor
### Tasks
<task read_first="apps/api/src/modules/orders/application/order.service.ts" acceptance_criteria="order.service.ts dispatches a delayed job and removes it if canceled.">
<action>
1. Modify `apps/api/src/modules/orders/application/order.service.ts`:
    - When order is marked `DONE` and `PAID`: If the Customer has `invitedById` and it's their first order, dispatch `schedule-referral-reward` to BullMQ with `{ jobId: orderId, delay: 15 * 24 * 60 * 60 * 1000 }`.
    - **[Review Fix]:** When an order is canceled, disputed, or refunded: Call `queue.remove(orderId)` to prevent the reward from executing if the 15-day window hasn't elapsed.
</action>
</task>

<task read_first="apps/api/src/modules/payments/infrastructure/queues/referral-reward.processor.ts" acceptance_criteria="A new processor handles the referral reward credit.">
<action>
1. Create `apps/api/src/modules/payments/infrastructure/queues/referral-reward.processor.ts`:
    - Process `schedule-referral-reward` jobs.
    - Increment `promoBalance` by 1000 (R$ 10,00 in cents) for both `refereeId` and `referrerId` wallets.
    - Create `WalletTransaction` records of type `PROMO_CREDIT` for both.
    - Increment `referralCount` for the `referrer`.
</action>
</task>
