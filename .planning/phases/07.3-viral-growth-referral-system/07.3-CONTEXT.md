<decisions>
## Implementation Decisions

### Invite Code Generation
- **Format:** Human-readable slugs (e.g., First Name + 3 random digits like `MARIA742`).
- **Data Model:** Add `inviteCode` (unique) to the `User` model, as the referral system is cross-role (Customers can invite Providers and vice versa).
- **Tracking:** Add `invitedById` to the `User` model.

### Reward Engine (D+15)
- **BullMQ:** Use a delayed BullMQ job (`schedule-referral-reward`) triggered when a referee's first order hits `DONE` and `PAID`. The delay is set to 15 days (15 * 24 * 60 * 60 * 1000 ms).
- **Wallet Integration:** Create a new transaction type or metadata flag in `WalletTransaction` (e.g., `type: PROMO_CREDIT` or `isPromotional: true`) to ensure this balance cannot be withdrawn as cash.
- **Discount Application:** 
  - For Customers: Intercept the order payment flow. If promotional balance exists, deduct up to R$ 10,00 from the `totalAmount` charged to the card.
  - For Providers: Deduct up to R$ 10,00 from the platform fee (`marketplaceFee`) calculated during the payout/escrow split.

### Anti-Fraud Engine
- **Velocity Limit:** Add `referralCount` and `referralLimit` (default 200) to the `User` model.
- **Sybil Detection:** Compare `deviceId` from `UserDevice` during registration. If a match is found with the referrer, silently drop the referral link (`invitedById = null`).
- **Payment Check:** During order payment, ensure the credit card fingerprint/hash hasn't been used by the referrer.

</decisions>
