Propósito: Automatizar a atualização de status dos payouts e reverter saldos de carteiras em caso de transferências malsucedidas sem intervenção manual.
Saída: Novo caso de uso de processamento de webhook, controlador atualizado, registro no módulo NestJS e cobertura de testes automatizados com Jest.
</objective>

  <files>apps/api/src/modules/payments/application/process-payout-webhook.usecase.ts</files>

  <action>
    Criar o arquivo `process-payout-webhook.usecase.ts` na pasta de casos de uso.
    O caso de uso deve:
    1. Receber `@Inject('PayoutRepositoryPort') private readonly payoutRepository: PayoutRepositoryPort` e `private readonly eventEmitter: EventEmitter2` no construtor.
    2. Conter uma função auxiliar criptográfica privada `verifySignature(rawBody: Buffer, signature: string, secret: string): boolean` que calcule o HMAC-SHA256 do rawBody e compare usando `crypto.timingSafeEqual` com a assinatura enviada.
    3. Tratar a chave de testes `sk_test_mock` de forma híbrida: se `process.env.PAGARME_SECRET_KEY === 'sk_test_mock'`, pular a validação de assinatura e retornar `true`.
    4. Na execução do método `execute(rawBody: Buffer, signature: string, payload: any): Promise<{ received: boolean }>`:
       - Validar assinatura. Se for inválida e não estiver em mock bypass, lançar um `UnauthorizedException` ou `BadRequestException`.
       - Extrair o ID de transferência externa do Pagar.me do body: `const externalId = payload.data?.id`. Se não houver, retornar `{ received: false }` ou ignorar se não for evento de transferência.
       - Ignorar eventos que não sejam do tipo `transfer.*` (apenas logs de debug, sem erro).
       - Buscar o payout correspondente pelo `externalId` usando `payoutRepository.findByExternalId(externalId)`. Se não encontrar, registrar log de aviso e retornar `{ received: false }` (evitando quebrar o fluxo para eventos desconhecidos).
       - Verificar idempotência: se o payout estiver em estado terminal (`PayoutStatus.PAID` ou `PayoutStatus.FAILED`), retornar `{ received: true }` imediatamente sem fazer nada.
       - Mapear o tipo de evento recebido (`payload.type`) para o status interno (`PayoutStatus`):
         - `transfer.processing` -> `PayoutStatus.PROCESSING`
         - `transfer.transferred` -> `PayoutStatus.PAID`
         - `transfer.failed` -> `PayoutStatus.FAILED`
         - `transfer.canceled` -> `PayoutStatus.FAILED`
       - Se for uma transição de status válida, atualizar o payout no repositório:
         - `payout.status = newStatus;`
         - `payout.updatedAt = new Date();`
         - `await this.payoutRepository.save(payout);`
       - Se o novo status for `FAILED`, despachar o evento de domínio `payout.failed` usando o EventEmitter para disparar o estorno de saldo automático (`ReverseFailedPayoutUseCase`):
         ```typescript
         this.eventEmitter.emit('payout.failed', {
           payoutId: payout.id,
           providerId: payout.providerId,
           amount: payout.amount.toString(),
         });
         ```
  </action>
