# Research: Phase 08.2 — Payout Resilience & Automation

## 1. Pagar.me Webhook Integration & Signature Verification

### Payload Event Structure (API v5)
Pagar.me v5 webhook notifications are HTTP `POST` requests sending a JSON body with the following structure:
```json
{
  "id": "evt_xxxxxxxxxxxxxx",
  "type": "transfer.transferred",
  "created_at": "2026-05-20T21:40:00Z",
  "data": {
    "id": "tr_xxxxxxxxxxxxxx",
    "amount": 150000,
    "status": "transferred",
    "recipient_id": "re_xxxxxxxxxxxxxx",
    "metadata": {
      "batchId": "uuid-do-lote"
    }
  }
}
```

### Event Mapping to PayoutStatus
We must handle the following events:
- `transfer.processing`: Indicates that the transfer is in progress. Map to `PROCESSING` status.
- `transfer.transferred` (or `transfer.success` in some contexts): Indicates successful settlement. Map to `PAID` status.
- `transfer.failed`: Indicates rejection. Map to `FAILED` status.
- `transfer.canceled`: Indicates cancellation. Map to `FAILED` status.

## 2. NestJS Raw Body Capture & Verification

To verify the signature cryptographically, we need access to the original, unparsed raw body payload.

### Step 1: Enable Raw Body in NestJS Application
In NestJS 9+, native support is enabled in `apps/api/src/main.ts` by passing `rawBody: true` in the creator options:
```typescript
const app = await NestFactory.create(AppModule, { rawBody: true });
```
This stores the raw buffer on the Express Request object as `request.rawBody`.

### Step 2: Validate the x-pagarme-signature Header
The signature sent by Pagar.me is the SHA256 HMAC of the raw body payload using the webhook secret.

**Cryptographic Validation logic:**
```typescript
import { Request } from 'express';
import * as crypto from 'crypto';

export function verifySignature(req: Request, webhookSecret: string): boolean {
  const signature = req.headers['x-pagarme-signature'] as string;
  if (!signature) return false;

  const rawBody = req.rawBody;
  if (!rawBody) return false;

  const computedHash = crypto
    .createHmac('sha256', webhookSecret)
    .update(rawBody)
    .digest('hex');

  try {
    return crypto.timingSafeEqual(
      Buffer.from(signature, 'hex'),
      Buffer.from(computedHash, 'hex')
    );
  } catch {
    return false;
  }
}
```

### Step 3: Hybrid Mock Signature Bypass for UAT
As decided in `08.2-CONTEXT.md` (D-02), when `PAGARME_SECRET_KEY` is `'sk_test_mock'`, signature verification should bypass and succeed without checking cryptographically:

## 3. Idempotency & Database Integration

### Repository Extension
We need to correlate webhooks (which contain `data.id` as the transfer external ID) to our internal `Payout` entities. 
We must add a query method `findByExternalId` to the repository port and adapter:

**In `PayoutRepositoryPort`:**
```typescript
findByExternalId(externalId: string): Promise<PayoutProps | null>;
```

**In `PrismaPayoutRepository`:**
```typescript
async findByExternalId(externalId: string): Promise<PayoutProps | null> {
  const raw = await this.prisma.payout.findUnique({
    where: { externalId },
  });
  if (!raw) return null;
  return this.toProps(raw);
}
```

### Transition & Idempotency Safety
To avoid double processing and race conditions (e.g. processing same event twice or after a status is final):
1. **Check Status Terminality:** Before processing any state change, fetch the Payout and check if its status is already `PAID` or `FAILED`.
2. **Short-Circuit on Terminal Status:** If status is already terminal, log a warning and return success `200 OK` (received: true) immediately.
3. **Dispatched Event Protection:** Transition to `FAILED` must trigger the `payout.failed` event exactly *once*. The usecase `ReverseFailedPayoutUseCase` already handles this properly.

```bash
POST http://localhost:3333/payments/webhooks/pagarme
Headers:

Body:
{
  "id": "evt_test",
  "type": "transfer.transferred",
  "data": {
    "id": "tr_mock_12345",
    "status": "transferred",
    "amount": 100000
  }
}
```
This will allow validating individual status transitions and Ledger/Wallet reconciliation in UAT tests cleanly.
