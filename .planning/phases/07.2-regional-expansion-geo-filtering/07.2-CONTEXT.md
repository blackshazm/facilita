<decisions>
## Implementation Decisions

### Data Modeling
- **D-01:** Create a new Prisma schema `geo` (`@@schema("geo")`) for `City` and `Neighborhood` entities.

### Catalog Availability Mapping
- **D-02:** Map availability at the **Category** level, not per-service (e.g., `CityCategoryAvailability` or similar join table).

### Matching Engine Strategy
- **D-03:** Refactor `MatchingEngine` to use 100% Array Intersection (`neighborhoodId IN (provider.serviceZoneIds)`).
- **D-04:** Remove PostGIS radial/distance calculations from the primary matching query to ensure <100ms performance.

### Data Seeding
- **D-05:** Use Prisma seed scripts (`prisma/seed.ts`) with a static JSON file containing IBGE data for initial MVP cities.

### the agent's Discretion
- Exact Prisma schema definitions for the `geo` models (fields like slug, ibgeCode, etc).
- Seeding script implementation details.
- Error handling for users outside supported cities.

</decisions>

<specifics>
## Specific Ideas

- The `Location` (GPS coordinate) of the provider is kept in the database but used ONLY for estimating ETA or secondary routing, not for the primary match.
- The matching query should leverage standard Postgres indexes on the array/join tables rather than spatial indexes.

</specifics>
