# Pattern Map — Phase 6.1: Operational Analytics & BI

## 1. Backend: Modular Hexagonal Architecture
We will replicate the structure of the `payments` module for the new `analytics` module.

### Analog: `apps/api/src/modules/payments`
- **Domain**: Logic for BigInt calculation and projection updates.
- **Application**: Use Cases for fetching aggregated data.
- **Adapters**:
    - **Inbound**: Event Listeners (using `EventEmitter2`).
    - **Outbound**: Prisma Repository for projection tables.

### Data Flow Pattern:
1. `DomainEvent` -> `AnalyticsEventListener` (Inbound Adapter)
2. `AnalyticsEventListener` -> `UpdateMetricUseCase` (Application)
3. `UpdateMetricUseCase` -> `MetricRepository` (Outbound Adapter)
4. `MetricRepository` -> `Prisma.daily_metric.upsert()`

## 2. Frontend: Admin Dashboard
We will extend the existing admin layout and use Server Components for data fetching.

### Analog: `apps/client/src/app/admin/page.tsx`
- **RBAC**: Protected by `layout.tsx` checking for `UserRole.ADMIN`.
- **Data Fetching**: Use `async/await` in the Page component.
- **Visualization**: Use `'use client'` for Recharts components.

## 3. Database: Prisma Projections
### Analog: `packages/database/prisma/schema.prisma`
- Add a new `analytics` schema (if using multi-schema) or prefix tables.
- Pattern for BigInt: `gmv BigInt @default(0)`.

## 4. Reporting: Streaming CSV
### Pattern:
- Controller uses `@Res({ passthrough: true })` and returns `StreamableFile`.
- Service uses `fast-csv` and pipes data from a Prisma cursor.
