# Phase Plan — 6.1: Operational Analytics & BI

## Overview
This phase implements the event-driven analytics module and the Backoffice dashboard for marketplace metrics.

## 1. Domain Boundary
**Goal**: Implement metric aggregation engine and management dashboard.
**Core Components**:
- `Analytics` module in the backend (Event-driven Read Models).
- Operational Dashboard in the admin frontend (Next.js 15 + Recharts).
- Streaming CSV export API.

## 2. [BLOCKING] Schema Push Required
This phase adds the `analytics` schema and `DailyMetric` model.
- **ORM**: Prisma
- **Push Command**: `npx prisma db push`
- **Verification**: `npx prisma studio` (check for analytics schema).

---

## 3. Execution Plan

### Wave 1: Database & Core Analytics Module
**Objective**: Setup the infrastructure for metrics persistence.

1. **[BLOCKING] Update Prisma Schema**
    - **Action**: Add `analytics` to `schemas` in `datasource db`. Add `DailyMetric` model with `BigInt` for `gmv` and `revenue`.
    - **Files**: `packages/database/prisma/schema.prisma`
    - **Verification**: `npx prisma db push` exits 0.

2. **Initialize Analytics Module**
    - **Action**: Create `apps/api/src/modules/analytics` with `core`, `application`, and `adapters` folders. Register in `AppModule`.
    - **Files**: `apps/api/src/modules/analytics/analytics.module.ts`
    - **Verification**: Server starts without errors.

### Wave 2: Event-Driven Aggregation
**Objective**: Synchronize transactional events with analytics projections.

1. **Implement Domain Event Listeners**
    - **Action**: Create listeners for `OrderDoneEvent` and `PaymentCapturedEvent`. Update `DailyMetric` using `upsert`.
    - **Files**: `apps/api/src/modules/analytics/adapters/analytics-event.listener.ts`
    - **Verification**: Manually emit event; `DailyMetric` table is updated.

2. **Metric Projection Logic**
    - **Action**: Implement `UpdateDailyMetricUseCase` to handle the business logic of aggregation (e.g., matching IDs, date normalization).
    - **Files**: `apps/api/src/modules/analytics/application/use-cases/update-daily-metric.usecase.ts`
    - **Verification**: Unit tests for aggregation logic pass.

### Wave 3: API & Export Logic
**Objective**: Expose metrics and implement report streaming.

1. **Metrics API Endpoint**
    - **Action**: Create `GET /api/analytics/daily` endpoint with `RolesGuard(ADMIN)`.
    - **Files**: `apps/api/src/modules/analytics/adapters/analytics.controller.ts`
    - **Verification**: `curl` returns JSON data for the last 30 days.

2. **Streaming CSV Export**
    - **Action**: Implement `GET /api/analytics/export` using `StreamableFile` and `fast-csv`. Pipe Prisma cursor to response.
    - **Files**: `apps/api/src/modules/analytics/adapters/analytics.controller.ts`
    - **Verification**: Clicking export in browser downloads a valid CSV file.

### Wave 4: Dashboard UI & Charts
**Objective**: Visualize KPIs in the Backoffice.

1. **Dashboard UI Refactor**
    - **Action**: Integrate `Recharts` components (`LineChart` for GMV, `BarChart` for Orders). Use Next.js Server Components for initial fetch.
    - **Files**: `apps/client/src/app/admin/page.tsx`
    - **Verification**: Dashboard renders charts with live data.

2. **Emerald 2.0 Polish**
    - **Action**: Apply responsive containers and consistent theme colors (Green/Emerald). Add loading skeletons.
    - **Files**: `apps/client/src/app/admin/components/metrics-chart.tsx`
    - **Verification**: Visual audit at 390px and 1440px.
