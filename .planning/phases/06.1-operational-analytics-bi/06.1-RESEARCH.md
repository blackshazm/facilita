# Research Phase 6.1: Operational Analytics & BI

## Overview
This research defines the technical implementation for the event-driven analytics engine and the management dashboard in the FACILITA Backoffice.

## 1. Analytics Module Architecture
Following the **Modular Hexagonal Evolutivo** pattern, we will create a dedicated `analytics` module.

- **Location**: `apps/api/src/modules/analytics`
- **Isolation**: The module will have its own domain logic and projection tables, independent of the transactional `orders` or `payments` modules.
- **Communication**: Asynchronous events via `EventEmitter2`.

## 2. Event-Driven Read Models
To ensure high performance without locking operational tables:

- **Aggregators**: Handlers in the `analytics` module will listen to:
    - `order.completed` -> Increment `orders_count`, update `gmv` (using BigInt).
    - `order.matched` -> Increment `matches_count`.
    - `payment.captured` -> Update revenue/payout metrics.
- **Projection Schema**:
    - `DailyMetric`: `date`, `gmv`, `orders_count`, `matches_count`, `revenue`.
    - `ProviderPerformance`: `providerId`, `completed_orders`, `average_rating`.

## 3. Frontend Dashboard (Next.js 15)
- **Server vs Client**:
    - **Server Components**: Fetch aggregated data from `/api/analytics` using standard `fetch` with caching.
    - **Client Components**: Use `'use client'` for Recharts components (`LineChart`, `BarChart`, `PieChart`).
- **ResponsiveContainer**: Mandatory wrapping for Recharts to align with **Emerald 2.0** fluid layout.
- **Library**: `recharts` for its declarative API and clean aesthetics.

## 4. Streaming Export (CSV)
- **Tech Stack**: `StreamableFile` (NestJS) + `fast-csv`.
- **Efficiency**: Use database cursors (Prisma `$queryRaw` or `findMany` with pagination) to pipe data directly into the CSV stream.
- **Memory Management**: Do not load all records into memory. Use Node.js streams to maintain a low memory footprint.

## 5. Validation Architecture (Nyquist)
- **Consistency Check**: Cross-validate aggregated `DailyMetric.gmv` with the sum of `Wallet` ledger entries for the same period.
- **UAT-01**: Verification of the "GMV vs Time" line chart accuracy.
- **UAT-02**: Verification of the CSV export file structure and content integrity.
