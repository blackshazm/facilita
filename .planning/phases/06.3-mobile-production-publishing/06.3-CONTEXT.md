# Phase Context — 06.3: Mobile Production & Publishing

**Date**: 2026-05-05
**Status**: Context Gathered

## Domain
The core domain for this phase is **Mobile Operational Readiness**. We are taking the Provider App from a development baseline to a production-hardened state by implementing professional CI/CD, reliable push notifications, secure manual KYC verification, and resilient offline access to critical data.

<spec_lock>
**Requirements are locked by SPEC.md.** Focus is exclusively on the following implementation decisions.
</spec_lock>

## Decisions

### 1. Identity & Security (KYC)
- **D-01: Private Document Storage**: All KYC photos (Selfies/Documents) will be stored in private cloud storage. Access is granted via **Pre-signed URLs** generated by the backend on-demand for Admin review.
- **D-02: Manual Approval Workflow**: Onboarding remains `PENDING` until an Admin manually verifies the photos in the Backoffice.

### 2. Infrastructure & Delivery (EAS)
- **D-03: Simplified Environments**: EAS Build will use two main profiles: `development` (local API) and `production`. The `preview` profile will point to the **Production API** to allow high-fidelity internal testing via TestFlight/Internal Track.
- **D-04: UserDevice Management**: Push tokens will be stored in a dedicated `UserDevice` table in the `identity` schema, allowing multi-device support and token invalidation logic.

### 3. Application Persistence (Offline)
- **D-05: AsyncStorage for Persistence**: The "Offline-First Lite" requirement will be implemented using `@react-native-async-storage/async-storage` for persisting the current active order and provider profile.
- **D-06: Explicit Connectivity Awareness**: The app will use `react-native-netinfo` to display a "No Connection" banner and block write operations (e.g., status updates) with clear error messages.

### 4. Push Notification Engine
- **D-07: Backend NotificationService**: A new module in the NestJS API will use `expo-server-sdk` to dispatch notifications to the Expo Push Service, triggered by domain events.

## Code Context & Patterns
- **Prisma**: Add `UserDevice` and `KycSubmission` models.
- **Backend Events**: Hook into `OrderMatchedEvent` and `MessageSentEvent`.
- **Mobile Patterns**: Use `AsyncStorage` hooks for local state persistence.
