# Cross-AI Plan Review — Phase 6.3

## Claude Review (Claude Code 2.0.26)

### Summary
The plan is well-structured in waves but contains significant gaps in security and production hardening. While the core approach (EAS, Pre-signed URLs) is sound, it underestimates the effort required for App Store compliance and secure PII handling.

### Key Strengths
- Clear wave-based parallelization with explicit blocking tasks.
- Correct use of pre-signed URLs for KYC uploads.
- Explicit device-level push token management.

### Key Concerns
- **HIGH: KYC Security**: No file validation (size/type), missing PII encryption, and indefinite URL expiry.
- **HIGH: Database Risk**: Use of `prisma db push` (destructive) instead of proper migrations.
- **HIGH: Store Compliance**: Missing code signing, privacy manifests, and metadata requirements.
- **MEDIUM: Push Spam**: No rate limiting or deduplication for notifications.

---

## Antigravity Internal Review (Expert Persona)

### Summary
The architecture respects the Modular Hexagonal principles by isolating the `NotificationModule`. However, the plan lacks operational resilience (BullMQ retries) and performance optimizations for the new tables.

### Key Strengths
- Good domain isolation for the new modules.
- "Offline Lite" scope is pragmatic and avoids over-engineering.

### Key Concerns
- **HIGH: Performance**: Missing database indexes on `userId` for the new `UserDevice` and `KycSubmission` tables.
- **MEDIUM: Resilience**: No retry/backoff configuration for the `NotificationService` (essential for unreliable push services).
- **MEDIUM: Privacy**: No LGPD consent flow mentioned for the capture of biometric data (selfie).

---

## Consensus Summary

### Agreed Strengths
- **Wave Structure**: Dependency management is clear and logical.
- **Architecture**: Choice of technologies (EAS, pre-signed URLs, AsyncStorage) is correct for the current project stage.

### Agreed Concerns
- **Security & Privacy (CRITICAL)**: Lack of validation for KYC uploads and missing encryption for sensitive documents.
- **Database Best Practices**: `db push` must be replaced by migrations for production safety.
- **Operational Hardening**: Missing rate limiting, performance indexes, and retry logic for notifications.

### Suggestions for Improvement
1. **Security**: Add task to validate file types/sizes and set short expiry (15m) for pre-signed URLs.
2. **Migrations**: Switch to `prisma migrate dev` with explicit naming and add indexes to new tables.
3. **Resilience**: Configure BullMQ retries and exponential backoff for the notification workers.
4. **Compliance**: Include tasks for EAS code signing and Apple/Google privacy manifests.
