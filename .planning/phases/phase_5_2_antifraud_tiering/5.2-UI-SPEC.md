# Phase 5.2 UI Specification — Anti-fraud & Tiering Engine

## 1. Overview
This design contract defines the Backoffice Dashboard (`/admin`) for the FACILITA marketplace. Operators will use this interface to monitor fraud alerts (Velocity and Geofencing violations) and manage provider tiers. The goal is to provide high visibility into suspicious activities and a seamless way to manage provider performance.

## 2. Visual Direction (Emerald 2.0)
The design follows the "Emerald 2.0" system, focusing on clarity, trust, and efficiency.
- **Primary Color**: Emerald 600 (`#059669`) - Used for primary actions, active states, and branding.
- **Secondary Color**: Slate 600 (`#475569`) - Used for text, secondary actions, and icons.
- **Background**: Slate 50 (`#f8fafc`) - Main background to reduce eye strain.
- **Surface**: White (`#ffffff`) - Cards, tables, and modals.
- **Alert Colors**:
  - Velocity Fraud: Rose 500 (`#f43f5e`) - High urgency (Exceeding 20 services/day).
  - Geofencing Alert: Amber 500 (`#f59e0b`) - Medium urgency (Check-in > 500m from target).
- **Typography**: Inter (Sans-serif). 
  - Headings: Semi-bold, Slate 900.
  - Body: Regular, Slate 700.

## 3. Component Specs

### 3.1 Sidebar Navigation
- **State**: Fixed, collapsible.
- **Items**:
  - **Overview**: Icon (LayoutDashboard) - Summary of fraud trends and tier distribution.
  - **Fraud Monitor**: Icon (ShieldAlert) - List of violations with real-time counters.
  - **Provider Tiers**: Icon (TrendingUp) - Tier management and performance stats.
  - **Audit Logs**: Icon (History) - Historical record of all admin overrides and reviews.

### 3.2 Data Tables
- **Design**: Clean, zebra-striped rows, borderless.
- **Badges**: Rounded, low-saturation background with high-saturation text.
  - Tiers: Bronze (Slate), Silver (Emerald), Gold (Amber).
  - Status: Payout Paused (Rose), Pending (Slate), Cleared (Emerald).

### 3.3 Review Modal
- **Header**: "Review Alert: [Provider Name]"
- **Content**: Split view layout. 
  - Left: Detailed violation metrics (Total services, Distance delta, Timestamps).
  - Right: Map integration showing Check-in vs. Order location or recent activity timeline.
- **Footer**: [Dismiss Alert] [Contact Provider] [Confirm Fraud/Suspend Payouts].

## 4. Interaction Flows

### 4.1 Fraud Resolution Flow
1. **Detection**: System flags a provider violation (e.g., Velocity > 20).
2. **Notification**: Admin sees a Rose-colored badge on "Fraud Monitor" in the sidebar.
3. **Review**: Admin opens the Monitor, clicks "Review" on the alert to inspect the provider's daily history.
4. **Action**: Admin determines if the behavior is anomalous.
5. **Outcome**: "Confirm Fraud" triggers an immediate payout suspension; "Dismiss" clears the alert for that specific instance.

### 4.2 Manual Tier Adjustment Flow
1. **Selection**: Admin navigates to "Provider Tiers" and filters for a specific provider.
2. **Analysis**: Inspects automated stats (30-day volume, ratings).
3. **Override**: Clicks "Edit Tier", selecting a new tier (Bronze/Silver/Gold).
4. **Validation**: Enters a mandatory "Reason for Override" for audit purposes.
5. **Sync**: UI and Backend update immediately, overriding the next daily automated job.

## 5. Security (RBAC)
- **Access Control**: All `/admin/*` routes are protected by a `RolesGuard`.
- **Identity**: Session token must explicitly contain the `ADMIN` role.
- **UI Safety**: The admin sidebar is hidden for non-admin users. Unauthorized access attempts to admin URLs redirect to a 403 Access Denied page with a descriptive toast notification.
