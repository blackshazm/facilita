# Specification — Phase 07.4: Operational Payout Dashboard

## 1. Context & Goals
Phase 7.4 focuses on providing administrative visibility and control over the automated payout system. While the backend logic for processing and scheduling payouts is complete (Phase 7.1), there is currently no way for internal staff to monitor, approve, or block transfers.

**Goal:** Create an Administrative API and Dashboard to manage the payout lifecycle, ensuring operational safety for high-value transfers.

## 2. Requirements

### REQ-01: Admin Payout Management API
- **Current State:** Payouts are stored in the database but only accessible via repository calls in internal services.
- **Target State:** REST API under `/admin/payouts` with endpoints for:
    - `GET /`: List all payouts with pagination and filters (status, provider, date).
    - `POST /:id/approve`: Move a `PENDING_APPROVAL` payout to `SCHEDULED`.
    - `POST /:id/block`: Move a `PENDING_APPROVAL` or `SCHEDULED` payout to `CANCELLED`.
- **Acceptance Criterion:** Endpoint returns 403 for non-admin users and correctly updates `PayoutStatus` for authorized admins.

### REQ-02: Operational Dashboard UI
- **Current State:** No UI exists for payout monitoring.
- **Target State:** A dedicated page in the client app (or a new admin sub-app) that:
    - Displays a table of payouts with status colors (Yellow for Pending, Green for Paid, Red for Blocked).
    - Highlights payouts awaiting approval (> R$ 2.000,00).
    - Provides action buttons (Approve/Block) for each record.
- **Acceptance Criterion:** Admin can successfully filter by "Pending Approval" and execute an action that reflects in the UI immediately.

### REQ-03: Audit & Safety Locks
- **Current State:** `FinancialAuditLog` exists but doesn't specifically track manual admin overrides.
- **Target State:** Every manual Approve/Block action must:
    - Log a `PAYOUT_MANUAL_OVERRIDE` entry in `FinancialAuditLog`.
    - Include the `adminId` and `reason` (optional) in metadata.
- **Acceptance Criterion:** Database query shows an audit log entry immediately after an admin approves a payout.

## 3. Boundaries

### In Scope
- Admin API endpoints for Payout management.
- Admin UI for payout monitoring and control.
- Integration with existing `FinancialAuditLog`.
- RBAC enforcement (Admin only).

### Out of Scope
- Automatic fraud detection algorithms (handled by Phase 5.2 engine).
- Bank data editing via this dashboard (handled in Provider Profile).
- Real-time WebSockets for payout status (Polled updates are sufficient).

## 4. Acceptance Criteria Checklist
- [ ] `AdminPayoutController` implemented with RBAC protection.
- [ ] Endpoints for List, Approve, and Block are functional and tested.
- [ ] Dashboard UI displays payout list with correct status mapping.
- [ ] Manual overrides generate a `FinancialAuditLog` entry.
- [ ] Non-admin users cannot access the `/admin` routes.
- [ ] Total released vs total pending payouts visible in dashboard summary.
